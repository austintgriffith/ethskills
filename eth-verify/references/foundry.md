# Foundry verification adapter

Use only in a discovered Foundry workspace. Record `forge --version`, the `cast`/`anvil` versions if used, and the Solidity compiler version actually selected. Foundry docs track current releases; match flags to the installed executable's `--help`, effective configuration and, for older versions, that release's sources/docs. These are selection instructions, not a declaration that all Foundry releases were exercised here.

1. Read `foundry.toml`, workspace scripts, CI, remappings and dependency pins/submodules. Record selected `FOUNDRY_PROFILE`, environment overrides and effective config (for versions supporting it, `forge config --json`). Redact RPC URLs and secrets before saving config. Contract/test paths, optimizer, EVM version and fork settings can differ by profile.
2. Prefer the project's existing targeted script. Otherwise inspect `forge test --help`; select the actual test path/contract/name with the supported match flags. Record cwd, profile, command, exit status and relevant test names/count. Zero selected tests is not a pass. Compilation alone cannot satisfy behavioral assertions.
3. Verify relevant revert/authorization, six- versus eighteen-decimal boundaries, rounding and economic roundtrips. Use existing fuzz/invariant configuration where appropriate; record run counts, seeds and minimized failures when available. Failed assumptions or discarded inputs can hide a case: inspect what was actually exercised.
4. For external integration, reproduce the test against a pinned fork block and known upstream network with the project's RPC mechanism. Record block number/hash, address/code identity and provider limitations without exposing endpoint credentials. Missing archive access is `BLOCKED`; do not substitute a mock and call it fork coverage.
5. Tests normally write only to their isolated EVM. Read config and scripts for FFI, external RPC mutations and subprocesses first. Do not add `--broadcast`, send transactions with `cast send`, or run a deployment script as a substitute for a contract test. Any Anvil account impersonation, balance changes or mining controls are restricted to verified isolated state owned by the run.

Capture failing traces/logs using locally supported verbosity or trace flags. Tie findings to the assertion, not just the command exit. When the frontend uses a different local node from forge's ephemeral VM, explicitly deploy/seed the authorized isolated frontend environment through project-supported commands; passing forge tests do not prove that browser target's deployment.

Official sources (current docs are not a version pin): [test overview](https://www.getfoundry.sh/forge/testing), [fork testing](https://www.getfoundry.sh/guides/fork-testing), [configuration](https://www.getfoundry.sh/config), [release history for installed-version matching](https://github.com/foundry-rs/foundry/releases). Use the installed version's help for exact CLI syntax.
